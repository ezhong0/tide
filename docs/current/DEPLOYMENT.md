### Docker Compose (Local Services - Optional) ✅

**Location**: `docker-compose.yml` (root)

**Use Case**: Local development only (optional - can use Railway directly)

**Services**:
1. **Redis 7**
   - Port: 6379
   - Volume: `redis-data`
   - Use: Caching, rate limiting, pub/sub

2. **Kafka 7.5**
   - Port: 9092
   - Volume: `kafka-data`
   - Use: Event streaming

3. **Zookeeper 3.8**
   - Port: 2181
   - Volume: `zookeeper-data`
   - Use: Kafka coordination

**Start Command**:
```bash
docker-compose up -d
```

**Stop Command**:
```bash
docker-compose down
```

**Logs**:
```bash
docker-compose logs -f [service]
```

**Note**: For production and staging, use Railway instead of Docker Compose.

## Railway Deployment 🚂

**Platform**: Railway (https://railway.app)
**Purpose**: Simplified deployment for all infrastructure and custom services

Railway manages:
- **Redis**: Railway-managed Redis (replaces Docker Compose and Redis Cloud)
- **Kafka**: Railway-managed Kafka (replaces Docker Compose and Confluent Cloud)
- **Custom Services**: AI, Email, Calendar, Workflow, Gateway services
- **Environment Variables**: Centralized config management
- **Automatic HTTPS**: SSL certificates and custom domains

### Railway Setup

**1. Install Railway CLI**:
```bash
npm install -g @railway/cli
```

**2. Login to Railway**:
```bash
railway login
```

**3. Create New Project**:
```bash
railway init
```

**4. Link Existing Project**:
```bash
railway link
```

### Deploying Services to Railway

**Deploy AI Service**:
```bash
cd packages/services/ai
```

**Deploy Email Service** (when ready):
```bash
cd packages/services/email

```

**Deploy Calendar Service** (when ready):
```bash

```

**Deploy Workflow Service** (when ready):
```bash
cd packages/services/workflow

```

**Deploy Gateway Service** (when ready):
```bash

```

### Railway-Managed Infrastructure

**Redis**:
- Add Redis plugin in Railway dashboard
- Connection URL available as `REDIS_URL` environment variable
- Automatic backups and persistence
- Replaces: Docker Compose (local) and Redis Cloud (production)

**Kafka**:
- Add Kafka plugin in Railway dashboard
- Connection URL available as `KAFKA_BROKERS` environment variable
- Automatic topic management
- Replaces: Docker Compose (local) and Confluent Cloud (production)

### Railway Environment Variables

Set environment variables via Railway CLI or Dashboard:

```bash
# Set variable for specific service
railway variables set SUPABASE_URL=https://ozrocykjomgcuphicqpg.supabase.co

# Set variable for all services
railway variables set --service-all SUPABASE_URL=https://ozrocykjomgcuphicqpg.supabase.co

# View all variables
railway variables
```

**Required Variables**:
- `SUPABASE_URL`
- `SUPABASE_SERVICE_ROLE_KEY`
- `ANTHROPIC_API_KEY`
- `OPENAI_API_KEY`
- `REDIS_URL` (auto-generated by Railway)
- `KAFKA_BROKERS` (auto-generated by Railway)

### Railway Monitoring

**View Logs**:
```bash
railway logs
```

**View Metrics**:
```bash
railway metrics
```

**Open Dashboard**:
```bash
railway open
```

### Railway Benefits

1. **Simplicity**: One platform for all infrastructure and services

4. **Automatic Scaling**: Services scale based on usage

6. **Git Integration**: Automatic deployments from GitHub
7. **Environment Management**: Easy staging/production separation

## Backup & Recovery

### Current (Development)
- **Database**: Automated daily backups by Supabase
- **Redis**: No persistence (ephemeral cache, local Docker)
- **Kafka**: No persistence (development mode, local Docker)
- **Code**: Git repository

### Production (Railway + Supabase)
- **Database**: Automated backups by Supabase (hourly with 30-day retention)
- **Redis**: Railway-managed Redis with automatic persistence and backups
- **Kafka**: Railway-managed Kafka with topic replication and retention policies
- **Services**: Railway maintains deployment snapshots and rollback capability
- **Code**: Git repository + Railway deployment history
